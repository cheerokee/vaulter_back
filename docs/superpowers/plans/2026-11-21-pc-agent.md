# Agente do PC e passo do cérebro: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o back aceita um PC como Hub (`kind = 'pc'`), entrega o passo do cérebro (prompt + RAG + modelo +
orçamento) ao agente que conduz o laço, e guarda a ACL da organização e a auditoria das ações.

**Architecture:** módulo novo `src/agents/` (catálogo de ferramentas, ACL, auditoria; depende de `hubs` e
`organizations` pelo que eles exportam). O passo do cérebro mora no `cloud` (é o dono do prompt, do modelo, do RAG e do
orçamento) e consome do `agents` a ACL e o catálogo, e do `conversations` a checagem do turno do agente e o prazo do
ack. `hubs` ganha `kind`; `cloud_terms` ganha `covers_agent`.

**Tech Stack:** NestJS 12, TypeScript 6, TypeORM 1.x, PostgreSQL 18 (RLS), pg-boss, Vitest, supertest.

**Spec:** `docs/superpowers/specs/2026-11-21-pc-agent-design.md` (ler junto; este plano argumenta a partir dela).

## Global Constraints

- Tudo na `develop`, commit por tarefa e push para `origin/develop` logo depois (`CLAUDE.local.md`). Mensagens em
  inglês terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Antes de fechar cada tarefa: `npm run build && npm test && npm run lint && npm run typecheck`; tarefas com banco ou
  módulo: também `docker exec vaulter-back-app npm run test:e2e`. Depois de cada migration, `npm run schema:check` e
  `migration:generate` vazio.
- Migrations novas a partir de `1792898800000`, em passos de `100000`, na ordem das tarefas.
- Texto em claro (histórico, resultados de ferramenta, trechos, prompt, argumentos, caminhos, URLs) **nunca** em log,
  Sentry, auditoria, payload de tarefa, banco ou resposta de erro. Só ids, contagens, nomes de ferramenta, códigos e
  versões.
- Nenhuma chamada de rede (modelo, embeddings, KMS) dentro de `uow.run`. Orçamento: `tryReserve` antes, `settle` ou
  `release` depois (`CLAUDE.md`, "Orçamento de IA").
- Fronteiras: `agents` depende de `hubs`, `organizations` e `conversations` (só a porta `HubConversationScope`) e
  nunca importa `cloud`; `cloud` importa `agents` e `conversations` só pela `application/` exportada; nenhum de
  `hubs`, `organizations` ou `conversations` importa `agents`. Domínio puro.
- Rotas do agente: `@HubAuth()` e só Hub `pc`; Hub `appliance` recebe **404 igual a rota inexistente** do Nest
  (`Cannot <METHOD> <url>`), como o `PlatformPermissionGuard`.
- Constantes da spec (exatas): `BRAIN_MAX_CALLS = 16`; corpo do passo ≤ 256 KiB; cada resultado de ferramenta ≤ 32 KiB;
  rate limit `brainStep` 600/h por Hub; catálogo ≤ 200 ferramentas; lote de auditoria ≤ 100; `AGENT_ACK_LEASE_MS =
  15 * 60_000`.
- Erros novos (type estável): 422 `agent-not-shareable`, 422 `cloud-not-active`, 422
  `cloud-terms-agent-not-accepted`, 409 `brain-step-not-owned`, 422 `brain-step-limit`, 409
  `agent-policy-version-stale`, 422 `agent-policy-invalid` (com `invalidRules: number[]`, índices).
- Mudou rota, corpo, erro ou limite de Hub: atualizar `docs/hubs/hub-lifecycle.md` no mesmo commit; módulo novo ou
  regra nova: `CLAUDE.md` no mesmo commit.

## Review Focus

1. **O agente mente no `history`** (diz que o autor da pergunta é o dono, ou inventa uma confirmação de documento):
   o back usa o autor gravado da mensagem `messageId` e o histórico decifrado pelo servidor para a trava do documento.
   Teste na Task 11 e na Task 12.
2. **O modelo chama uma ferramenta que não foi oferecida** (alucinada, negada, ou de outra categoria): nunca sai em
   `toolCalls`; vira resultado de erro no turno seguinte dentro do mesmo passo. Teste na Task 11.
3. **A ACL muda entre dois passos da mesma resposta**: cada passo recalcula ferramentas e `effect` com a versão atual e
   devolve `policyVersion`. Teste na Task 11.
4. **O Hub perde o executor no meio do laço** (desvínculo, desregistro, troca de executor): o passo seguinte dá 404
   `conversation-not-found` e não reserva orçamento. Teste na Task 10.
5. **O espaço sai da nuvem ativa no meio do laço**: 422 `cloud-not-active`, sem custo, e o prazo do ack segue valendo
   para a mensagem voltar à fila. Teste na Task 10.

  function callEffect(rules: AgentRule[], userId: string, tool: AgentToolDef, input: unknown): AgentEffect;
